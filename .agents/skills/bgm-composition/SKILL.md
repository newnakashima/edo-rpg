# BGM を作曲する

このプロジェクトの BGM は、スーパーファミコン期の雰囲気を出すため、音楽生成 AI を使わずに AI エージェント自身が作曲する。
作曲したものは、曲の設計図（`.song`）→ MIDI（`.mid`）→ Ogg Opus（`.opus`）の順に書き出す。このスキルは MIDI までを扱い、`.opus` への書き出しは [bgm-render スキル](../bgm-render/SKILL.md) で行う。

AI が作曲すると、コード進行と旋律を別々に考えてしまい、強拍で旋律とコードがぶつかる、非和声音が解決しない、低音がコードと違う、といった音楽理論的に不自然な曲になりやすい。
このスキルは、コードを先に決めて旋律をその上に書く手順と、`scripts/bgm/song.py` による機械的な検査で、それを防ぐ。

## 守ること

- **音楽生成 AI や既存の曲を使わない。** 音はすべて `.song` に自分で書く。実在の曲の旋律やコード進行をそのまま写さない。
- **コード進行を先に決め、旋律はその上に書く。** 旋律を先に書いてから後でコードを付けない。
- **`song.py check` のエラーを 0 件にする。** エラーが出たら、旋律・コード・低音のどれかを直す。`!`（意図した不協和音）で消してよいのは、その音でしか出せない効果を狙う場合だけで、そのときは行の前のコメントに意図を書く。エラーを消すためだけに `!` を付けない。
- **警告は 1 件ずつ読み、直すか、残す理由を書く。** 残す警告は、理由を作業の報告と `.song` のコメントに書く。
- **薄い編成にしない。** 旋律・分散和音・低音・太鼓だけの 4 本の曲は、ファミコンのように聞こえる。[theory.md の 5](theory.md#5-スーパーファミコンの-jrpg-らしい厚みを出す) に従って、旋律の重ね・和音の層・動きの層・低音・リズム隊（ドラムキット + 和太鼓）で 8 音を使い切る。
- **ピアノロールを見てから仕上げる。** 検査が通っても、動機のくり返しがない、山がない、などは検査では分からない。画像を見て確かめる。
- **作曲の中身を決めるのはこのスキルの手順。** [theory.md](theory.md)（作曲の決まりごと）と [format.md](format.md)（書式）を読んでから書き始める。見本は [example.song](example.song)。

## ファイルの置き場所

| もの | 場所 |
| --- | --- |
| 曲の設計図 | `audio-src/bgm/<ID>.song`（ID は `docs/audio.md` の表の ID。例: `bgm_town`）|
| MIDI | `audio-src/bgm/<ID>.mid`（`song.py midi` が書く。設計図と一緒にコミットする） |
| 書き出した曲 | `public/assets/bgm/<ID>.opus`（bgm-render スキルで書く） |

必要なもの: Python 3.10 以上、numpy、Pillow（ピアノロール用）、ffmpeg（libopus 付き。書き出し用）。

## 手順

### 1. 曲の設計を書き出す

`docs/audio.md` の表から、作る曲の場面と雰囲気を確かめ、次を決めて作業のメモに書く。

- 場面と雰囲気（表の文言を、音の言葉に言い換える。例:「旅の歩み」→ テンポ 132、民謡音階、三味線の 8 分の刻み）
- テンポ、拍子、調（旋法）。和の曲は [theory.md の 4](theory.md#4-和の音階で書く) から選ぶ
- 形式（例: `A B`、`I` + `A A2 B`）、各区間の小節の数（8 の倍数）、ループ部分の長さ（秒。小節数 × 拍数 × 60 ÷ テンポ）
- 編成: [theory.md の 5](theory.md#5-スーパーファミコンの-jrpg-らしい厚みを出す) の層ごとに、楽器・パターン・音の数を決める。同時発音数の合計を 7〜8 音にする（8 音まで）
- 旋律のパートの名前は `melody` にする（書き出しの報告で、旋律が埋もれていないかを確かめるため）
- ループするか（ファンファーレ・宿屋はしない）

### 2. コード進行を決める

区間ごとに、小節ごとのコードを決める。[theory.md の 1](theory.md#1-コード進行を先に決める) に従う。

- 各コードの機能（T・S・D）を書き添え、流れが T → S → D → T になっているか確かめる
- 4 小節目（半終止）・8 小節目（終止）の形を決める
- ループの最後の小節から頭へ戻るつながりを決める
- 調にないコードを使うなら、副属和音・借用和音・ナポリのどれかを書き添える

ここで一度 `chords` の行だけを書いた `.song` を作り、`song.py check` でコードの度数の一覧と警告を見てもよい（旋律のパートを書かない区間は休みになる）。

### 3. 旋律を書く

[theory.md の 2](theory.md#2-旋律はコードの上に書く) の「骨組み → 肉付け」で書く。

1. まず、1〜2 小節の動機を決める（リズムと音の形）
2. 各小節の強拍に、コードトーンを置く（骨組み）。区間ごとに音域を決め、フレーズに頂点を 1 つ作る
3. 骨組みの間を、経過音・刺繍音・倚音・掛留音でつなぐ。非和声音は前か後ろを必ず順次進行にする
4. 動機をくり返し・ずらし・変化させて、8 小節のまとまりを作る（新しい音形ばかり並べない）

### 4. 編成を書く（伴奏・重ね・低音・打楽器）

[theory.md の 5](theory.md#5-スーパーファミコンの-jrpg-らしい厚みを出す) の層を、手順 1 で決めた編成のとおりに書く。

- **旋律の重ね**: `follow=melody shift=-6d`（6 度下）などで、別の楽器に旋律をなぞらせる。区間によって `off` にしたり、その区間だけ対旋律を書いたりして変化をつける
- **和音の層**: 弦・合唱・笙のパターン。`voices=2` で音の数を節約する。戦闘は `block:push8` や `block:stab` で刻む
- **動きの層**: 箏・ハープ・ピチカートの `arp:`、または対旋律（旋律がのびる所で動かし、反対向きに動かす）
- **低音**: `bass:` のパターンか、自分で書く（コードが変わる所はそのコードの最低音）
- **リズム隊**: バスドラム・スネア・ハイハットで骨組みを作り、大太鼓・締太鼓・鉦で和の色を重ねる。区間の頭にクラッシュ、4・8 小節目にタムのおかず。大文字と小文字で強弱をつける
- 音量と定位は [theory.md の 5](theory.md#5-スーパーファミコンの-jrpg-らしい厚みを出す) の目安から始める

### 5. 検査して直す

```bash
python3 scripts/bgm/song.py check audio-src/bgm/<ID>.song
```

- **エラー** をすべて直す。メッセージは「どの区間の何小節目の何拍目の、どのパートの、どの音が、どのコードに対して何か」と直し方を示す。旋律の音を変えるか、コードを変えるか、その場で判断する（旋律の流れを優先するならコードを、コード進行を優先するなら旋律を変える）
- **警告** を 1 件ずつ読み、直すか、残す理由を書く
- `-v` で情報（倚音・掛留音として通した音、借用和音の読み方）もすべて見て、意図どおりか確かめる
- 「強拍・長い音のうちコードトーン」の割合は 70% 以上を目安にする
- 「1 小節あたりのパートの数」の警告（薄い）が出たら、層を足す

エラーと警告を直したら、もう一度 `check` する。エラーが 0 件になるまでくり返す。

### 6. ピアノロールを見る

```bash
python3 scripts/bgm/song.py roll audio-src/bgm/<ID>.song -o /tmp/<ID>_roll.png
```

画像を Read ツールで開き、次を確かめる。薄い黄色の段がそのときのコードトーン、緑の音がコードトーン、青がテンション、赤がアボイド、紫が調にない音である。

- 旋律（枠付き）に、くり返す動機が見える
- フレーズごとに山があり、区間ごとに音域の対比がある
- 旋律が伴奏（灰色）より上にあり、埋もれていない
- 赤・紫の音が、強拍や長い音にない（あれば検査で倚音として通った音。意図どおりか確かめる）

気になる所があれば手順 3 か 4 に戻る。

### 7. MIDI に書き出す

```bash
python3 scripts/bgm/song.py midi audio-src/bgm/<ID>.song
```

エラーがあると書き出さない。続けて [bgm-render スキル](../bgm-render/SKILL.md) で `.opus` に書き出す。

## 完了時の報告

曲ごとに、次を簡潔に報告する。

- ID、テンポ、調、形式、ループ部分の長さ（秒）、パートと楽器、同時発音数
- コード進行（区間ごとに度数で）
- 検査の結果（エラー 0 件、残した警告とその理由）
- 書き出したファイル（`.song`、`.mid`、`.opus`）
