# 効果音を波形から合成する

このゲームの効果音は、1 つの音につき 1 本の Python スクリプトで波形を合成し、Ogg Opus（48 kHz）に書き出す。
PixelLab の `create_sound_effect` などの、外部の効果音生成モデルは使わない。録音した素材も使わない。
どんな音にするかは、エージェントが「何がどう鳴るか」を思い浮かべて、音の素・形・色の組み合わせとしてスクリプトに書く。

## 守ること

- **外部の効果音生成モデルや素材を使わない。** 音はすべて `scripts/sfx/sfxlib.py` の部品（または numpy・scipy で自分で書いた処理）で作る。
- **物の鳴り方から組み立てる。** 「何が・何に当たって・どう響いて・どう消えるか」を先に言葉で分け、その部分ごとに音を作って重ねる（下の「組み立て方」）。音色を思いつきで足し引きするより、狙いが外れたときに直す場所が分かる。
- **要件は場面と聞こえ方の言葉で書く。** 正本は `docs/audio.md` の「効果音（SE）」の表（場面・聞こえ方・長さ・優先）。表にない音は、先に表に足す。
- **戦闘の音は 0.6 秒以内。** 戦闘は 1 つの出来事を 650 ms で進めるので、次の出来事の音と重ならないようにする（戦闘の後のページの se_levelup は除く）。
- **何度も鳴る音ほど控えめにする。** se_cursor・se_message・se_ok などは、何十回鳴っても耳に障らないよう、短く、高すぎず、`level` を下げる。
- **押してから鳴るまで遅らせない。** 頭に無音を置かない（立ち上がりを滑らかにするのはよいが、10 ms 以内に聞こえ始める）。
- **音を聞けないことを踏まえて確かめる。** エージェントが判定できるのは、書き出せたか、長さ、頭の遅れ、終わりの切れ目、音割れ、大きさのそろい具合、波形とスペクトログラムの見た目が狙いの形どおりか、までである。良し悪しは、書き出した音をユーザーに聞いてもらって決める。

## 準備

一度だけ入れる（クラウドのセッションでは、新しいセッションごとに要る）。

```bash
python3 -c "import numpy, scipy, PIL" 2>/dev/null || pip install -q numpy scipy pillow
ffmpeg -hide_banner -encoders | grep -q libopus && echo ok
```

## ファイルの置き場所

| 置き場所 | 中身 | コミット |
| --- | --- | --- |
| `sfx/sounds/<ID>.py` | 効果音 1 つを合成するスクリプト。ID は `docs/audio.md` の ID（`se_cursor` など） | する |
| `public/assets/audio/se/<ID>.ogg` | ゲームで鳴らす音（Ogg Opus、48 kHz） | する |
| `sfx/.preview/` | 波形とスペクトログラムの画像、書き出し前の WAV、試聴用に並べた音 | しない |

道具は `scripts/sfx/` にある。

| 道具 | すること |
| --- | --- |
| `sfxlib.py` | 合成の部品（スクリプトが `from sfxlib import *` で読む） |
| `build.py` | スクリプトを実行し、大きさをそろえて Ogg Opus に書き出し、画像を作る。`--sheet` で試聴用に並べた音も作る |
| `check.py` | 書き出した音を読み戻して調べ、まだ作っていない音を優先ごとに数える |
| `sfxcheck.py` | `build.py`・`check.py` が使う測定と画像（スクリプトからは使わない） |
| `game_check.mjs` | ゲームを動かし、効果音が読み込めて、場面で実際に音を出しているかを確かめる |

## スクリプトの書き方

```python
# 決定: 澄んだ短い一打。se_cursor より明るくはっきり（0.1 秒）
from sfxlib import *

bell = modal([note("E6"), note("E6") * 2.76, note("E6") * 5.4], decays=[0.04, 0.02, 0.008],
             amps=[1.0, 0.45, 0.2], seconds=0.12)
tick = bandpass(noise(0.003), 3000, 9000) * env_exp(0.003, 0.0007) * 0.6
sound = Sound("se_ok", fade(mix(bell, tick), fade_out=0.02), title="決定", level=-3)
```

- 1 行目の注釈に、`docs/audio.md` の場面・聞こえ方・長さを書き写す（スクリプトだけ見ても狙いが分かるように）。
- 最後に `sound = Sound(ID, 音, title=..., level=...)` を作る。音は 1 次元（モノラル）か `(サンプル数, 2)`（ステレオ）。左右に動く音・広がる音でなければモノラルにする。
- ユーザーの感想で直した点など、書き出すたびに思い出したいことは `Sound(..., notes=["..."])` に書く（書き出しのたびに「メモ:」として出る）。
- 大きさは `build.py` がそろえるので、スクリプトの中で音量を合わせなくてよい（重ねる部分どうしの割合だけ決める）。全体を小さく・大きく鳴らしたいときは `level`（dB）で指定する。
- 乱数は `noise()` などの部品か `rng` を使う。`build.py` が ID から種を決めるので、何度書き出しても同じ音になる。

### 部品

時間はすべて秒、高さは Hz。高さを受け取る部品は、数（そのときは長さも渡す）か、`sweep` などで作った配列を受け取る。

| 種類 | 部品 | 使いどころ |
| --- | --- | --- |
| 高さの動き | `sweep(f0, f1, 秒)`・`glide([(秒, Hz), ...], 秒)`・`vibrato(高さ, 秒, rate, depth)`・`note("E6")` | 上がる・下がる・揺れる。`note` は音名を Hz に |
| 発振 | `sine`・`saw`・`square`・`triangle`・`fm(高さ, ratio, index)`・`partials(高さ, 倍率, 強さ)` | 澄んだ音は sine、明るい音は saw・square を lowpass で丸める。金物の濁りは fm、鐘・鈴は非整数倍の partials |
| ノイズ | `noise(秒, "white"/"pink"/"brown")`・`crackle(秒, density)` | 風・息・擦れ・火・水は noise をフィルタで色付け。ぱちぱち・ざらざらは crackle |
| 叩く・はじく | `modal(周波数, decays, amps, strike=)`・`resonator(音, Hz, decay)`・`pluck(Hz, 秒)` | 木・金物・鐘・鈴は modal（短い noise を strike に渡すと打った手ざわりが出る）。弦は pluck |
| 形 | `env_exp(秒, decay)`・`env_adsr(秒, ...)`・`env_points([(秒, 量), ...], 秒, curve="db")`・`tremolo(音, rate)` | 打つ音は env_exp、続く音は env_adsr、自由な形は env_points |
| 色 | `lowpass`・`highpass`・`bandpass`・`sweep_filter(音, 周波数の配列, kind, q)`・`drive(音, 量)`・`bitcrush(音, bits, hold)` | 動くフィルタで「シュッ」「ゴウッ」。drive で太く荒く。bitcrush でからくりの機械らしさ |
| 空間 | `reverb(音, 秒, wet)`・`echo(音, delay, feedback)`・`stereo(音, pan)`・`widen(音)` | 寺の鐘は長い reverb、洞窟は echo。残響は長さが伸びるので、戦闘の音では短く |
| 組み合わせ | `mix(a, (b, 秒), ...)`・`place(a, b, 秒)`・`concat(a, b)`・`fade(音, in, out)`・`trim(音, 秒)`・`silence(秒)`・`db(-6)` | 部分を時間をずらして重ねる・つなぐ |

部品で足りなければ、numpy・scipy で処理を書いてよい。何度も使う処理になったら `sfxlib.py` に足す。

### 組み立て方

効果音は、だいたい次の 3 つの部分に分けると組み立てやすい。

1. **当たり（トランジェント）**: 最初の数 ms の、打つ・はじく・弾ける瞬間。短いノイズを帯域で絞ったものが多い。これがないと、ぼやけて遅れて聞こえる。
2. **体（ボディ）**: その物らしさ。木なら短い共鳴、金物なら長く尾を引く非整数倍の響き、布や水ならノイズの色、刃物なら高い共鳴。
3. **尾（テール）**: 消え方。残響・やまびこ・転がる・崩れる。長さの目安を超えやすいのはここなので、短い音では削る。

聞こえ方の言葉からの当たりの付け方（出発点であって決まりではない）:

| 言葉 | 当たりの付け方 |
| --- | --- |
| 乾いた・木 | 1〜4 kHz の共鳴を 5〜20 ms で消す。残響なし |
| 澄んだ・鈴・金物 | 非整数倍（2.76 倍・5.4 倍など）の響きを重ね、高い方ほど早く消す |
| 低い・重い・鈍い | 40〜150 Hz の sine を下へ `sweep` し、pink・brown のノイズを lowpass で重ねる。drive で太く |
| 鋭い・裂く | 高い帯域へ速く動く `sweep_filter`。当たりを強く |
| 上がり調子・晴れやか | 音の高さを上へ並べる（短い音を concat で 2〜4 つ） |
| 濁る・揺らぐ | fm の index を大きく、vibrato・tremolo で揺らす |
| 遠ざかる | lowpass を下げながら音量を下げる。stereo の pan を動かす |

## 手順

### 1. 要件を書く

作業のメモに、作る音ごとに次を書き出してから作り始める。

- ID と、`docs/audio.md` の場面・聞こえ方・長さ・優先（表になければ先に足す）
- 何がどう鳴る音か（当たり・体・尾に分けて、それぞれ何の音か）
- 同じ場面で続けて鳴る音や、比べられる音（se_ok と se_cancel、se_slash と se_critical など）との違い
- `level`（何度も鳴るから下げる、大きな出来事だから上げる、など）

### 2. スクリプトを書く

`sfx/sounds/<ID>.py` に、手順 1 の分け方どおりに部分ごとに作って `mix` で重ねる。部分には名前を付ける（`tap`・`body`・`tail` など）。

### 3. 書き出す

```bash
python3 scripts/sfx/build.py se_ok se_cancel
```

`public/assets/audio/se/<ID>.ogg` と、確認用の画像 `sfx/.preview/<ID>.png` ができる。出力には、長さ（と目安）、大きさ、ピーク、[注意] が出る。
スクリプトの誤り（例外・無音・NaN など）は、その効果音だけ [失敗] として知らせ、ほかの効果音は書き出す。[注意] か [失敗] があれば終了コードは 1 になる。
同じスクリプトからは同じバイト列の .ogg ができるので、音を変えていない効果音は書き出し直しても git の差分に出ない。

大きさは、100 ms ごとに測った聞こえる大きさ（K 特性、LUFS と同じ尺度）の最大を、効果音の間でそろえる（-14 LUFS に `level` を足した値）。ピークは -1 dBFS を超えないようにする。

### 4. 確かめる

画像（`sfx/.preview/<ID>.png`）を Read で開いて見る。上が波形（音量の形）、下がスペクトログラム（縦が周波数 50 Hz〜20 kHz の対数、明るいほど強い）、赤い縦線が長さの目安である。
次の項目を ○ か × で判定し、× があれば直して手順 3 からやり直す。

1. 書き出しが [注意] なしで終わった（[注意] が出たら、意図したものか確かめ、意図していなければ直す）
2. 長さが目安に近い（戦闘の音は 0.6 秒以内）
3. 波形の形が、手順 1 で書いた当たり・体・尾の並びどおり（当たりが最初に立っている、尾が目安の線までに消えている）
4. スペクトログラムで、狙った帯域に音がある（「低い」のに高い帯域が明るい、「澄んだ」のに広い帯域にノイズが広がっている、などがない）
5. 比べられる音と区別が付く（高さ・長さ・明るさのどれかが、はっきり違う）
6. 手順 1 に書いた聞こえ方に照らして、自分の見立てで違和感がない

続けて、書き出したもの全体を調べる。

```bash
python3 scripts/sfx/check.py
```

長さ・頭の遅れ・終わりの切れ目・音割れ・大きさのそろい具合（`level` を除いて、全体の中央から 4 dB 以上ずれていないか）を調べ、最後に、表の効果音のうちまだ作っていないものを優先ごとに挙げる。

### 5. 聞いてもらう

```bash
python3 scripts/sfx/build.py --sheet se_cursor se_ok se_cancel
```

指定した音を書き出したうえで、0.6 秒ずつ空けて並べた `sfx/.preview/sheet.ogg` ができ、何秒からどの音かが出る。
これと各音の `.ogg` をユーザーに送り（SendUserFile）、何秒からどの音かを添えて聞いてもらう。
ユーザーの感想で直すときは、その点を手順 1 の要件に足してやり直す。感想が「こういう音」という一般的なものなら、上の「当たりの付け方」の表にも足す。

### 6. コミットする

- コミットするのは `sfx/sounds/` と `public/assets/audio/se/`。`sfx/.preview/` はコミットしない。
- `scripts/sfx/sfxlib.py` の部品を変えたら、その部品を使う音がすべて変わる。`python3 scripts/sfx/build.py --all` で書き出し直し、`git diff --stat public/assets/audio/se/` で変わった音を確かめる。

## ゲームで鳴らすとき

- 効果音は `public/assets/audio/se/<ID>.ogg` に置く。シーンは `src/systems/audio.ts` の `playSe(id)` を呼ぶ。書き出した効果音は、起動時に `src/data/seTracks.ts` がファイル名から拾い、`src/ui/sePlayer.ts`（Web Audio）が鳴らす（`.ogg` を置いたら、ページを開き直す・ビルドし直すと鳴る）。
- どの場面でどの音を鳴らすかは、`docs/audio.md` の「効果音（SE）」の表と「コードでの鳴らし方（効果音）」に書いてある。
- 効果音を足したり、鳴らす所を変えたりしたら、ゲームの中で鳴るかを `node scripts/sfx/game_check.mjs` で確かめる（先に `npm run dev` を起動しておく）。書き出した効果音がすべて読み込めて 1 つずつ音を出すこと、最初の操作の前は鳴らないこと、タイトル・フィールドのメニュー・出入り・出会いの戦闘・イベント（野狐）で鳴るはずの音が鳴ることを調べる。音が出ているかは効果音の出口の大きさで測る（-60 dBFS より大きいか）。問題があれば終了コード 1。
