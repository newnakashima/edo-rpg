# MIDI を Ogg Opus に書き出す

[bgm-composition スキル](../bgm-composition/SKILL.md) で作った MIDI を、`scripts/bgm/render.py` でスーパーファミコン風の音にして `.opus` に書き出す。

## 音源のしくみ

`scripts/bgm/synth.py` は、スーパーファミコンの音源（S-DSP）の特徴をまねて鳴らす。

- 楽器ごとに短い波形（サンプル）を 1 つ数式で作り、BRR（4 bit の圧縮）で粗くする
- 音の高さはサンプルの読み出し速度で変える（ガウス補間で高域が少し丸くなる）。持続する楽器はサンプルの後ろをくり返し読む
- 弦・金管・合唱は、少しずつ高さをずらした数人分の音を重ねたサンプル（合奏の厚み）。打楽器・撥弦の一部は、部屋の響きをサンプルに焼き込んである（SNES のサンプルは響きごと録った生の音が多いため）
- ADSR の音量変化、遅れてかかるビブラート、全体にかかるエコー（遅延・フィードバック・8 タップの FIR。右だけ 16 ms 遅らせて左右に広げる）
- 打楽器はキットの中の位置（左右）を持つ
- 音程のある 1 回読み切りのサンプル（撥弦など）は、最後の 25% でなめらかに 0 まで下げてある（長い音がサンプルの終わりで「ぷつっ」と切れないように）
- 仕上げに、全体を目標の音量にそろえ、はみ出すピークだけをリミッターで抑える（ループ部分は輪にして処理するので、つなぎ目で音量は跳ばない）
- 内部は 32000 Hz で鳴らし、書き出すときに 48000 Hz に変える
- 楽器はトラック名（`song.py` が `楽器名:パート名` で書く）で選ぶ。ほかの方法で作った MIDI は、GM のプログラム番号で近い楽器を選び、10 チャンネル目は打楽器にする

## 守ること

- **書き出したら、報告の数値を必ず読む。** エージェントは音を聞けないので、長さ・ループの位置・つなぎ目の段差・音量・同時発音数で確かめる。「書き出せた」だけで完了にしない。
- **警告が出たら直す。** つなぎ目で音が跳ぶ、音割れのおそれ、8 音を超える、途中に長い無音、のどれかが出たら、作曲の側（`.song`）に戻って直し、MIDI から書き出し直す。
- **音量は曲ごとにそろえる。** `--loudness` は全曲で同じ値（初期値 -18 dBFS）にする。変える場合は理由を書く。
- **音色の調整は `synth.py` で行い、すべての曲を書き出し直す。** 1 曲のためだけに音色を変えない（ほかの曲の聞こえ方が変わるため）。

## 手順

### 1. 書き出す

```bash
python3 scripts/bgm/render.py audio-src/bgm/<ID>.mid -o public/assets/bgm/<ID>.opus
```

オプション:

- `--wav <ファイル>`: 確かめるための WAV（48000 Hz）も書く。リポジトリには入れない（`/tmp` などに書く）
- `--echo 遅延ms フィードバック 量`: エコーを変える（省略時は `.song` の `echo =`）。曲の雰囲気を変えたいときは `.song` の方を直す
- `--bitrate 96k`: ビットレート（初期値 96k。容量を減らすなら 64k まで）
- `--loudness -18`: 目標の実効値（dBFS）

### 2. 報告を確かめる

`render.py` は、書いた `.opus` を読み戻して、次を表示する。項目ごとに、基準を満たすか確かめる。

| 項目 | 基準 |
| --- | --- |
| 読み戻した長さ | 書いた長さとの差が 0 サンプル（Opus の頭の無音の補正が正しく効いている） |
| ループ | `LOOPSTART` + `LOOPLENGTH` がファイルの長さと等しい。秒数が `.song` の検査で出たループ部分の長さと合う |
| つなぎ目の段差 | 「問題なし」。ふだんの隣り合うサンプルの差より大きいと、ループで「ぷつっ」と鳴る |
| 音量 | 実効値が目標（-18 dBFS）付近、最大が -1 dBFS 以下。リミッターで下げた量が 6 dB を超える（警告が出る）なら、打楽器など一部の音だけが大きすぎるので、そのパートの `vol=` を下げる |
| パートごとの音量 | 耳の感じ方に近い K 特性（ITU-R BS.1770）で重み付けした値で比べる。打楽器以外では旋律（`melody`）がいちばん大きい。旋律の重ね・和音の層は旋律より 4〜8 dB 小さい。低音・打楽器は旋律と同じくらい（0〜-3 dB）。旋律がほかのどのパートよりも 3 dB 以上大きいと、旋律だけが浮いて聞こえる（警告が出る）。外れたら `.song` の `vol=` を直す |
| 同時発音数の最大 | 8 以下 |
| 使った楽器 | `.song` の [parts] と一致する |

### 3. 波形の様子を見る（任意）

聞けない代わりに、`--wav` で書いた WAV から、時間ごとの音量（パートが消えていないか、区間の切り替わりで音量が急に変わらないか）を見る。例:

```bash
python3 - <<'EOF'
import wave, numpy as np
w = wave.open('/tmp/<ID>.wav'); x = np.frombuffer(w.readframes(w.getnframes()), dtype='<i2').reshape(-1, 2) / 32768
sec = 48000
for i in range(0, len(x) // sec):
    rms = np.sqrt(np.mean(x[i * sec:(i + 1) * sec] ** 2))
    print(f"{i:3d}s {20 * np.log10(rms + 1e-9):6.1f} dB " + "#" * int(max(0, 60 + 20 * np.log10(rms + 1e-9))))
EOF
```

### 4. ゲームでのループ

- `.opus` の Vorbis コメントに `LOOPSTART` と `LOOPLENGTH`（48000 Hz のサンプル数）を書いてある。RPG ツクールなどと同じ形式である
- イントロのない曲は `LOOPSTART=0` なので、ファイル全体をそのままくり返せばつなぎ目なく聞こえる（ループの最後の余韻・エコーはループの頭に重ねてある）
- イントロのある曲は、再生側で `LOOPSTART` 秒から `LOOPSTART + LOOPLENGTH` 秒までをくり返す（Web Audio の `AudioBufferSourceNode` の `loopStart` / `loopEnd`）
- ループしない曲（`loop = no`）は余韻の後でフェードアウトしてある

### 5. 一覧を更新する

`docs/audio.md` の曲の表に、書き出したファイルを書き足す（まだの曲と区別できるようにする）。

## 完了時の報告

書き出した `.opus` ごとに、長さ、ループの位置（秒）、容量、音量（実効値・最大）、同時発音数を報告する。警告が出て直した場合は、何をどう直したかも書く。
